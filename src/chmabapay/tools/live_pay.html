How to read the result

Banking app accepts the code and you can pay → the offline EMVCo build routes to the right account. Confirmed on a real phone: this needs Tag 30.01 set to a real Bakong account, never the link slug.
ABA's page never flips to PAID → verified: link.payway.com.kh/<slug> is a static Nuxt template. It always serves order_details.status="OPEN" and amount="0.00" and carries no per-transaction data, so this source cannot confirm a payment. A poll against it stays PENDING forever by construction — that is not a payload problem.
Cross-check with the Bakong Open API (md5 lookup) is the only source that can confirm a payment, because Bakong's ledger is indexed by the QR md5. It is currently 401 Unauthorized — no BAKONG_API_TOKEN is configured. Set one before trusting any status.
The QR is encoded by the backend at /api/v1/khqr/render.svg — ECC H, 4-module quiet zone. Payload generation: POST /api/v1/khqr/from-link. Status: POST /api/v1/khqr/probe-aba-status (re-reads the public ABA page, no credentials). Dev-only surface.
